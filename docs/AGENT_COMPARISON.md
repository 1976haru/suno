# 생성 에이전트 비교 절차

지시문 18 (TASK C-4). "클로드코드와 코덱스 중 어느 쪽이 더 나은 가사·프롬프트를
내는가"를 사후에 답할 수 없던 문제(§C-1)를 해결하기 위한 실측 절차다.
**같은 조건에서 두 에이전트를 비교하는 것이 핵심** — 슬롯 배정(장르·BPM·구조 템플릿·
킬링포인트)은 앱이 이미 고정해서 내려보내므로, 결과 차이는 순수하게 에이전트의
가사·프롬프트 작성 능력 차이다.

## 0. 전제

- 두 에이전트 모두 **같은 브릿지 지시문**을 받는다 (`Step3Generate.tsx`의 "Claude Code용
  지시문 복사" 버튼이 만드는 텍스트를 그대로 사용 — 별도로 다시 만들지 않는다).
- 텍스트 생성만 하므로 **Suno 크레딧이 들지 않는다**. 6번(수노 청취 비교)만 크레딧을 쓴다.
- 비교는 **최소 3세트씩** 쌓인 뒤에 의미가 있다 (`src/core/agentComparison.ts`의
  `MIN_SETS_FOR_AGENT_COMPARISON` — 앱의 집계 화면도 이 미만은 "표본 부족"으로 표시하고
  숫자를 비교로 보여주지 않는다).

## 1. 채널·컨셉 고정, 브릿지 지시문 1회 생성

같은 채널, 같은 컨셉(예: "60년대가 생각나는 올드팝")으로 Step 3에서 지시문을 한 번만
만든다. ".txt로 다운로드" 버튼으로 저장해 두면 두 에이전트에게 완전히 동일한 텍스트를
줄 수 있다.

## 2. 각 에이전트에 넣어 A.json · B.json 받기

같은 지시문 텍스트를 Claude Code와 Codex(또는 비교하려는 다른 에이전트)에 각각
붙여넣는다. 두 응답을 서로 다른 파일명으로 저장한다(예: `A_claude-code.json`,
`B_codex.json`).

## 3. 가져오기 시 생성 에이전트 지정

Step 3의 "곡 JSON 가져오기" 위에 있는 **"이번 세트를 만든 생성 에이전트"** 선택창에서
그 세트를 실제로 만든 에이전트를 고른 뒤 각 파일을 가져온다. 마지막 선택값이 다음
가져오기의 기본값으로 남으므로, A.json → B.json 순서로 가져올 때 선택을 바꾸는 것을
잊지 않는다. (선택을 잊어도 가져오기 자체는 막히지 않는다 — `'other'`로 정직하게
기록될 뿐이다.)

## 4. 측정

```bash
npx tsx scripts/audit.ts --pack A.json
npx tsx scripts/audit.ts --pack B.json
npx tsx scripts/audit.ts --pack A.json --cross B.json
```

`--cross`는 두 세트 사이의 장면/제목/훅 중복을 실측한다 — 같은 컨셉으로 두 번
생성했으니 겹침이 있는 것 자체는 정상이지만, 과도한 중복은 둘 다 같은 실패 패턴을
공유한다는 신호다.

## 5. 비교 항목

`scripts/audit.ts --pack`의 출력에서 그대로 읽는다 — 별도로 다시 계산하지 않는다.

| 항목 | 어디서 |
|---|---|
| qualityScore 평균·최저·80점 이상 곡 수 | `--pack` 출력 끝의 "실제 발매물 qualityScore" 블록 |
| stylePrompt 길이 · 인트로 모순 · 리드 중복 선언 | `[프롬프트]` 카테고리 |
| 가사 단어수 · 어휘 최대 반복 | `[가사]` 카테고리 |
| distinctChoice 이행률 | `[워크스페이스] 곡별 다른 시도 이행률` |
| 시대 표기 primary 비중 | `[워크스페이스] stylePrompt 시대 표기` |
| excludePrompt 고유값 | `[프롬프트]` 카테고리 |
| 약속 이행도 | `[약속 이행도]` 카테고리 |
| 작곡 지시 유출 / 소품 상태 모순 (지시문 17) | `[가사]` 카테고리 |

## 6. 수치가 비슷하면 청취로 판정

자동 측정으로 우열이 뚜렷하지 않으면, 각 세트에서 3곡씩만 골라 Suno에 넣어 직접
듣는다. 여섯 곡뿐이므로 크레딧 부담이 크지 않다.

## 7. 집계 화면에서 누적 확인

세트를 가져올 때마다(3번) `generatedBy`가 기록되므로, "🎧 무엇이 잘 먹히나" 화면의
**"생성 에이전트별 실측"** 섹션에서 여러 비교 세션이 누적된 결과를 볼 수 있다. 이
화면은 세트 수·곡 수·qualityScore 평균·평가 결과(좋음/별로 비율)만 보여줄 뿐, 어느
에이전트가 낫다고 앱이 결론 내리지 않는다 — 판단은 하루가 한다. 세트 3개 미만인
에이전트는 "표본 부족"으로만 표시된다.

## 하지 말 것

- 슬롯 배정을 에이전트마다 다르게 하지 말 것 — 그러면 비교가 슬롯 차이인지 에이전트
  차이인지 구분할 수 없다.
- 표본 3세트 미만으로 결론 내지 말 것.
- qualityScore 하나만 보고 판정하지 말 것 — 위 표의 항목을 함께 본다(qualityScore는
  구조 준수만 측정하며, 개념 적합도·다양성 등 다른 축은 별도다).
