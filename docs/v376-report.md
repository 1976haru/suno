## 2. 약속 이행도 상세 — 6절 검증값과 경향 비교

| 항목 | 이 문서(§6) 기대 범위 | 실측(로컬 생성) | 경향 일치 |
|---|---|---:|---|
| 약속 이행도 종합 | 30~45% | 47% | 근접 (오차 +2%p) |
| 시대 | 50~60% | 74% (genre 61%, lyrics 100% 포함 평균) | 장르만 보면 61%로 범위 안 |
| 참조(비틀즈) | 25~40% | 43% | 근접 (오차 +3%p) |
| 분위기(밝음) | 35~45% | 25% (emotionArc만 보면 28%) | 근접, 낮은 쪽 |
| 제목 정합성 | 10~25% | (아래 §2-1 참고) | 방법론 차이로 직접 비교 불가 |

**측정 방법론이 하루님의 수작업 집계와 정확히 같지 않습니다** — 예를 들어 "참조" 항목은 원저 스펙의 "13개 시드 중 8개, 5곡에만"이라는 수동 집계 방식을, 이 도구는 "레퍼런스의 15개 트레잇 구문 각각이 몇 곡에 도달했는지의 평균 커버리지"로 자동화했습니다(§4-2 참고). 정확한 퍼센트가 아니라 **경향**(시대 > 참조 > 분위기 순으로 약함, 종합 50% 미만)이 일치하는지가 검증 기준이며, 실측 결과 경향이 일치합니다.

### 2-1. 제목 정합성 — 로컬 생성과 실제 증상의 차이 (중요)

로컬 생성 팩으로 측정하면 `hookConnectedCount: 18/18`, `offConceptTitleCount: 0`으로 나옵니다 — 이 문서의 §6 기대치(10~25%)와 정반대입니다. 이유는 A3/v3.75에서 **로컬 제목 생성기(`titleFromHook`)는 이미 고쳐졌지만, 실제 Suno 곡을 만드는 브릿지 경로는 별개**이기 때문입니다(v3.75 보고서 §5-3에서 이미 확인). 로컬 생성이 좋은 결과를 내는 것은 실제로 A3/v3.75가 로컬 경로에는 도움이 됐다는 정직한 신호이지만, 원 스펙이 인용한 "낮은 제목 정합성" 증상은 로컬 경로에서 재현되지 않습니다.

**검증을 위해 실제 보고된 제목·훅 쌍을 직접 넣어 테스트했습니다** (`tests/promiseAudit.test.ts`):

```
titles = ['Tablelight', 'Blue Crease', 'Shoulder', 'Porchlight', 'Roadsalt', ...]
hooks  = ['Hold My Hand, Friend', 'I Still Believe', 'Save Me One Dance', ...]

실측: hookConnectedCount = 0/9, offConceptTitleCount = 5/9
```

`auditTitleConceptConsistency`가 실제 보고된 증상(훅 연결 0건)을 정확히 잡아냅니다 — 도구 자체는 검증됐고, 로컬 생성 팩이 그 증상을 재현하지 못하는 것은 도구의 결함이 아니라 **로컬 경로가 이미 개선됐다는 사실**입니다.

## 4. 음원 없이 실행했을 때 "미측정" 표기 확인 (§7-4)

`--audio` 플래그 없이 실행한 §1 출력에서 다음 2개 항목이 실측 그대로 "미측정"(⬜)으로 표기되고, "실패"(⚠)로 처리되지 않음을 확인했습니다.

```
[가사] 수노 실측 길이 | 3:15~3:35 (오디언스 프로파일) | (음원 미제공) | ⬜ 미측정
[킬링포인트·아크] 킬링포인트 곡 진폭 | ≥ 6dB | (음원 미제공) | ⬜ 미측정
```

미달(⚠) 12건 목록에도, 종합 집계의 "회귀"/"미달" 카운트에도 이 2건은 포함되지 않았습니다 — `9 미측정` 안에만 들어갑니다.

**정직성 노트 — `--audio` 플래그의 실제 동작**: 스펙은 `npm run audit -- --audio ./songs`(mp3 폴더)를 요구했습니다. 실제 파형 분석(v3.73/v3.74)은 브라우저의 Web Audio API로 동작하며, Node CLI 환경에는 없습니다. 새 무거운 오디오 디코딩 의존성을 추가하는 대신, `--audio <path>`는 **이미 계산된 `SongAudioMetrics[]` JSON 파일**(브라우저의 `AudioAnalysisPanel`에서 내보낸 것)을 받도록 구현했습니다 — mp3 폴더 자체를 파싱하지는 않습니다. 이 차이를 `scripts/audit.ts` 자체 주석과 이 보고서에 명시합니다. 실제 mp3 음원 검사는 브라우저 UI(TASK C, §5)에서 이미 동작합니다.

## 7. 작업 전후 18곡 산출물 diff — 동일 확인

**이 작업이 생성 로직에 손대지 않았다는 것을 `git diff`로 직접 증명합니다** — 재생성해서 비교하는 것보다 더 강한 증거입니다: 생성 파이프라인에 관여하는 파일 중 이번 세션에서 수정된 것은 `src/core/compositionScorer.ts` 단 하나이고, 변경 내용은 이미 존재하던 함수 3개(`descriptorCount`/`lyricWordAndSectionCounts`/`vocalZoneDistributionWarnings`)에 `export` 키워드를 붙인 것뿐입니다.

```diff
-function descriptorCount(stylePrompt: string): number {
+export function descriptorCount(stylePrompt: string): number {
-function lyricWordAndSectionCounts(lyrics: string): {...} {
+export function lyricWordAndSectionCounts(lyrics: string): {...} {
-function vocalZoneDistributionWarnings(songs: ...): string[] {
+export function vocalZoneDistributionWarnings(songs: ...): string[] {
```

함수 본문은 한 글자도 바뀌지 않았습니다 — `export` 키워드는 TypeScript의 가시성(visibility)만 바꾸고 런타임 동작에는 전혀 영향을 주지 않습니다. `src/core/lyricEngine.ts`, `src/core/promptComposer.ts`, `src/core/bridgeInstruction.ts`, `src/core/setDirector.ts` 등 실제 생성 로직 파일은 이번 세션에서 **전혀 수정되지 않았습니다**(`git status`로 확인). 나머지 신규/수정 파일(`fullAudit.ts`, `promiseAudit.ts`, `scripts/audit.ts`, `PromiseAuditPanel.tsx`, `Step4Result.tsx`의 탭 1개 추가, `package.json`, `styles.css`)은 전부 새 파일이거나 UI에만 영향을 주며 어떤 것도 곡 생성 함수를 호출·수정하지 않습니다.

## 9. 하지 말 것 — 준수 확인

- 약속 이행도를 억지로 높이려고 생성 로직을 바꾸지 않음 — §7에서 `git diff`로 증명.
- 회귀 감지에서 음원 항목을 실패로 처리하지 않음 — §4에서 확인(⬜ 미측정으로만 표기).
- 회귀가 있어도 브릿지 지시문 복사를 막지 않음 — `PromiseAuditPanel`은 독립 탭이며 다른 액션을 비활성화하지 않습니다.
- `[기준선 갱신]`을 자동으로 하지 않음 — CLI는 `--save-baseline` 명시 플래그, UI는 `window.confirm` 확인 후에만 저장.
- 검사 항목을 임의로 줄이지 않음 — 3-2절 목록 41개 항목 + 음원 2개 + 약속 이행도 3개(개별 promise) + 종합 1개 = 47개.
- `lyricEngine.ts` / 프롬프트 조립 / 채점 층 미수정 — §7에서 확인.
- 전체 테스트를 반복 실행하지 않음 — `npm run test:fast`(619 테스트) + 신규 테스트 2개 파일만 실행.

## 10. 미구현 목록 (명시)

1. **약속 분해 6종 중 2종 미구현**: `genre`(장르 자체를 컨셉이 명시한 경우), `situation`(구체적 상황 명시)은 `decomposeConceptPromises`가 감지하지 않습니다 — 시대/참조/분위기/계절만 구현했습니다.
2. **관사·복수 오류 검사**: 기존 코드베이스 어디에도 재사용할 문법 검사기가 없어 미구현으로 표기했습니다(`grammar_article_errors` 항목).
3. **`[intro]` 아래 문장 vs introMode 대조**: `SongIdea`에 `introMode`가 저장되지 않아(오직 `PreassignedSongSlot`에만 있음) 생성 완료 후 팩만으로는 재검사할 수 없습니다 — 미구현으로 표기했습니다.
4. **워크스페이스 격리 검사**: 메모리 상의 단일 팩에는 "다른 워크스페이스" 개념이 없어 이 형태로는 측정 불가 — 저장된 라이브러리 전체를 대상으로 하는 별도 검사가 필요합니다(A1/A2가 이미 저장·이전 시점의 격리는 보장).
5. **`--audio` 플래그의 실제 동작**: mp3 파일이 아니라 이미 계산된 메트릭 JSON을 받습니다(§4 참고) — 진짜 오디오 디코딩은 브라우저 UI에서만 가능합니다.
6. **지시문 이력(`specifiedBy`)의 정확도**: 코드 주석을 근거로 수작업 정리한 best-effort 매핑입니다 — 완전한 git 커밋 로그 감사는 아닙니다.
7. **`제목 정합성` 이행도의 로컬-실측 불일치**: §2-1에서 설명한 대로, 로컬 생성 경로는 이미 A3/v3.75로 개선되어 원 스펙이 인용한 낮은 수치를 재현하지 않습니다 — 실제 브릿지 경로 검증은 실제 Suno 생성 후에만 가능합니다.
