## 1. 핵심 설계 — TASK B "한 곳을 거치게" 원칙

`src/core/workspaceScope.ts`가 유일한 접근 계층입니다. 두 가지 서로 다른 저장 형태에 서로 다른 전략을 씁니다:

- **레코드형 IndexedDB 저장소** (팩/훅/평가/영상/사용량/배치/오디오 테이크): 각 레코드에 `workspaceId` 필드를 붙이고 `scopeFilter()`로 조회 시 필터링. `workspaceId`가 없는 레코드는 `senior-oldpop`으로 간주(마이그레이션 이전 데이터에 대한 안전망).
- **전역 블롭형 localStorage/설정 값** (커스텀 채널 배열, 최근 장르, 다양성 배분 설정 등): `scopedKey()`로 키 자체에 워크스페이스를 접두 — 필터 후 재저장 방식은 다른 워크스페이스의 데이터를 통째로 덮어쓸 위험이 있어 배제했습니다.

`suno-weaver-cache`(API 응답 캐시)와 BYOK API 키(`byok:*`)/이미지 설정은 스펙 §3-3 그대로 공유 유지했습니다 — 손대지 않았습니다.

### 1-1. 실제 버그 발견·수정 (엔지니어링 과정 정직 공개)

`scopeFilter()`/`listPacks()`의 최초 설계는 "다른 워크스페이스를 잠깐 들여다볼 때 `setCurrentWorkspace()`로 전역을 바꿨다가 복원"하는 방식이었습니다. **워크스페이스 선택 화면에서 각 카드의 세트 개수를 보여주려고 5개 워크스페이스를 동시에 조회하자, React 18 StrictMode의 개발 모드 이펙트 이중 실행이 이 공유 전역 변수에 대한 경쟁 상태를 실제로 발생시켰습니다** — 실제 브라우저에서 "시니어 올드팝 세트 0개"로 잘못 표시되는 것을 발견했습니다(실제로는 2개). 근본 수정: `scopeFilter(items, forWorkspace?)`와 `listPacks(workspaceId?)`에 명시적 파라미터를 추가해 공유 가변 상태 자체를 없앴습니다. 수정 후 실제 브라우저에서 "세트 2개 · 마지막 8/1"로 정확히 표시됨을 재확인했습니다. 이 경쟁 상태와 수정 내용은 `tests/workspaceScope.test.ts`/`tests/library.test.ts`에 회귀 테스트로 남겼습니다.

## 7. 미구현 항목 (명시)

1. **비-시니어 4개 워크스페이스의 실제 내용**(archetypeIds/terms/hiddenFeatures/artistName) — 스펙 자신이 "골격만, B1~F1에서 채움"이라 명시한 범위. 빈 배열/객체로 남겨두었고, 진입 시 "준비 중" 안내로 막아 억지로 시니어 데이터를 보여주지 않습니다.
2. **진입 화면의 "설정" 버튼** — `SettingsModal`이 `channel`/`channels` prop(채널별 용량 예측 등)에 강하게 결합돼 있어, 워크스페이스 선택 전 컨텍스트에서 그대로 재사용하기 어려웠습니다. 비활성 버튼으로만 존재("워크스페이스를 먼저 선택하면 설정을 열 수 있습니다" 툴팁). API 키 등 공유 설정은 위저드 진입 후 기존 경로로 정상 접근 가능합니다.
3. **`suno-weaver-library` 내부 보조 저장소**(personas/progress/concept_cache/concept_history) — 스펙 §3-2 표가 명시한 것은 "저장된 팩"(메인 packs 스토어)뿐이라 그 범위만 워크스페이스 분리했습니다. 이 보조 저장소들은 packId/channelId에 종속돼 있어 실질적 누출 위험은 낮지만, 명시적으로 분리하지는 않았습니다.
4. **hooks/videos/batch 저장소의 Node 단위 테스트** — 이 3개(+ ratings/usage/audio takes 중 일부 경로)는 Node vitest 환경에 IndexedDB가 없어 원래부터(v3.74 이전부터) 순수 함수만 단위 테스트가 가능했던 기존 제약입니다. workspaceId 스코핑 로직은 코드 검토 + 실제 브라우저 IndexedDB 직접 조회로 검증했습니다.
5. **동요 워크스페이스의 DistroKid 아티스트명 분리 실동작** — `WorkspaceDefinition.artistName` 필드는 존재하지만 kr-kids/jp-kids가 골격 단계라 실제 값이 없습니다. D1/E1/F1의 범위입니다.
