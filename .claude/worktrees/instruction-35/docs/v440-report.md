## 1. TASK A 조사 결과 및 수정 (지시문 3단계 순서대로)

**1단계 — 브릿지 지시문에 단어수 지시가 있는가?**
있었습니다. `promptComposer.ts`의 `MIN_LYRIC_WORDS=215`/`MAX_LYRIC_WORDS=230`(→ `resolveLyricRange`를 통해 실제 지시문에 반영)은 이미 215-230이었습니다.

**2단계 — 있다면 문구가 약한가, 아니면 서로 모순되는 지시가 있는가?**
모순이 있었습니다. `bpmLengthControl.ts`의 `BPM_LENGTH_TIERS`(트랙별 "Length target" 컬럼으로 렌더링되어 `bridgeInstruction.ts`의 또 다른 CRITICAL 줄로 전달됨)의 하위 2개 tier(62-78 BPM, 79-92 BPM)가 각각 180-200단어, 200-220단어를 지시하고 있어 팩 전체 215-230 CRITICAL 지시와 정면으로 모순됐습니다. 더 구체적인(트랙별) 지시가 이기므로, 62-92 BPM 밴드에 배정된 트랙(시니어 채널 실측 기준 18곡 중 8곡)은 애초에 215 미만을 목표로 지시받고 있었습니다.
- **수정**: 4개 tier 전부 하한 215 이상으로 재중심화 — `[215,225]/[218,228]/[220,230]/[222,232]`. 실제 렌더링된 지시문의 "Length target" 컬럼과 팩 레벨 215-230 CRITICAL 줄이 이제 모순 없이 일치함을 확인(스크립트로 실제 지시문 텍스트 출력 대조).

**3단계 — 로컬 경로(`lyricEngine.ts`)도 짧은가? 섹션/라인 수 문제인가?**
그렇습니다. `lyricEngine.ts`는 `resolveLyricRange`를 전혀 참조하지 않고, 라인풀 인출 횟수가 v3.70 시절 175-205 목표(~190단어)에 고정되어 있었습니다. 실측 137-177단어/곡.
- **1차 수정**(병행 세션, 커밋 `728bf87`): `opening`/`bridge` 섹션을 모든 역할(shortOpenerRoles 제외)로 확대 이중 인출 — 137-177 → 149-208.
- **2차 수정**(이 세션, 커밋 `8adc899`):
  - `takeUniqueLines`에 훅/제목 텍스트 충돌 가드 추가(정확히 일치가 아니라 **부분 문자열 포함**도 재시도) — 이전에 R1 회귀(훅 텍스트가 무관한 줄에 섞여 들어감)로 되돌렸던 코러스2 이중 인출을 근본 원인을 고쳐서 재활성화.
  - `situationLines`를 구조 템플릿별로 조건부 이중 인출: T4(브릿지·프리코러스 둘 다 없음, 6섹션)와 T3(프리코러스만 있고 브릿지 없음)만 대상. T1(둘 다 있음)과 T2(별도 브레이크다운 섹션 보유)는 시도했으나 각각 230 초과(240-255) 및 236-253으로 과다 확대되어 제외.
  - **단어수만 늘리지 않았습니다** — 프리코러스는 "정확히 2행" 구조 계약(기존 테스트로 보호됨)을 그대로 유지했고, 늘어난 것은 전부 기존에도 있던 섹션(오프닝/브릿지/코러스2/버스1 필러)의 **인출 횟수**입니다. `lyricEngine.ts`의 문장 생성 로직(템플릿 문구 자체)은 건드리지 않았습니다.

**결과**: 8개 컨셉 재측정(아래 §3 표) — 대부분 215-232 범위. **알려진 예외 1건**: 트랙 1(콜드오픈)은 v3.11(TASK I1) "첫 후렴까지 빨리 도달"이라는 별개의 의도적 설계로 인해 항상 짧게(~173단어) 렌더링됩니다. 이번 작업에서 의도적으로 건드리지 않았습니다 — 목표와 무관한 이전 설계 결정을 조용히 뒤집기보다 그대로 보고합니다.

**★ 수노 실측 3곡 — 미검증.** 이 세션은 로컬 스크립트로만 검증 가능하며 실제 Suno 렌더링 API 호출 권한이 없습니다. 가사를 늘린 것이 실제 재생 시간을 3:15-3:35 범위 밖으로 밀어내는지는 실제 Suno 생성 후에만 확인 가능합니다. `estimateSongLengthSec`(BPM+구조템플릿 기반, 단어수와 무관한 별도 추정치)는 이번 수정 전후로 값이 변하지 않았고, 느린 BPM+T1 조합이 여전히 3:45를 초과하는 사례가 있으나 이는 v3.82부터 있던 별개의 기존 이슈이며 관문1이 이미 감지·차단(§5의 "무시하고 진행"으로 우회 가능)하고 있습니다 — 이번 단어수 작업이 새로 만든 문제가 아닙니다.

## 2. TASK B 실제 누출 문장 (원문)

**고정 fixture** (`tests/fixtures/realBridgePack.json`)에서 발견, 수정 전에는 미탐지:
> `"You said, the string will hold it tight"` — "string"과 "hold" 사이에 조동사 "will"이 끼어 있어 기존의 즉시-인접 패턴이 놓쳤습니다. `hold`/`holds`/`held`도 `ARRANGEMENT_SUBJECT_VERBS`에 아예 없었습니다.

**수정**: `SUBJECT_LEAK_PATTERN`이 이제 조동사·부사 최대 2단어(닫힌 목록: will/can/could/would/should/must/may/might/is/was/are/were/has/have/had/do/does/did/still/softly/gently/slowly/quietly/now/again/always/never/just)까지 허용하며, `hold`/`holds`/`held`를 동사 목록에 추가했습니다. 오탐 방지 철학(임의 단어 건너뛰기 금지)은 유지했습니다.

**부수 발견 — 오탐 1건 수정**: 로컬 생성기의 `(instrumental hook, band plays the melody, no lyrics, 2 bars)` 지문(스테이지 디렉션, 실제로 불리지 않음)이 매 팩마다 4곡씩 오탐되고 있었습니다. `isLyricBodyLine`이 "no lyrics"를 명시한 줄을 제외하도록 수정 — 8개 컨셉 로컬 생성 결과가 오탐 수정만으로 0/18 누출로 떨어졌습니다.

**bridgeInstruction.ts에 누락 지시문 추가**: "instrument/arrangement/production terms... 를 가사 줄의 주어로 쓰지 말 것"이라는 CRITICAL 지시가 실제로 코드에 없었음을 확인(v4.4 문서가 언급한 "v3.60 TASK A-1" 텍스트는 존재하지 않았음 — 있던 것을 복구가 아니라 **신규 추가**). 단일팩·멀티셋 경로 양쪽에 추가.

**★ 새로 발견한 근본 원인 (이번 세션 최종 검증 중 발견, 미수정)**: 탐지 정확도를 높인 결과, `data/genreLibrary/index.ts`의 일부 장르가 자체 `lyricFlavorImages`에 `'worn guitar strings'`/`'quiet strum'` 같은 **악기 단어 자체를 이미지로** 갖고 있음을 발견했습니다. C8("젊은 시절 춤추던 토요일 밤")이 이 장르를 배정받으면 다음과 같은 실제 가사가 나옵니다:
```
T3: "The worn guitar strings holds the evening"
T7: "The worn guitar strings keeps shining"
T2: "The quiet strum echoes my footsteps"
```
탐지(`findArrangementVocabularyInLyrics`)는 정확히 잡아내고 있습니다(10/18곡) — 문제는 탐지가 아니라 **장르 데이터 테이블 자체**가 문장의 주어 자리에 들어갈 수 있는 악기 이미지를 갖고 있다는 것입니다. 이를 고치려면 (a) `genreLibrary`의 flavor image 데이터를 수정하거나 (b) `lyricEngine.ts`의 모티프-주어 삽입 로직을 바꿔야 하는데, 전자는 "어휘 뱅크 재작성"(v4.5 범위 제외 지정), 후자는 "문장 생성 로직 변경"(이번 문서 §9 명시적 금지)에 해당해 **이번 v4.4 범위에서는 수정하지 않고 정직하게 보고만 합니다.**

## 8. TASK F — 프롬프트 길이 미해결 사유 (정직한 보고)

`vocal` 프롬프트 원자에 `shortForm`을 부여해 압축이 실제로 줄어들도록 시도했으나, `safeTarget`(소프트 예산)을 350-650 근처로 낮추자 **장르 간 스타일 유사도 안전장치**(`tests/promptBudgetLoopGuard.test.ts`, 기준 0.35)가 실측 0.36으로 회귀함을 발견했습니다. safeTarget을 0.35 통과 수준(≈800)까지 완화하면 프롬프트 길이는 거의 줄지 않습니다(870→800대). **장르 고유 원자를 먼저 자르지 말라는 이번 문서 §9의 명시적 제약과 정면으로 충돌**하므로, 프롬프트 길이 단축을 강행하지 않고 `styleLimitValue`(변경 없음)로 되돌렸습니다 — 안전장치를 깨면서까지 길이만 맞추는 것은 "체크를 통과시키기 위해 느슨하게 만들지 말 것"이라는 이번 세션 전체의 원칙에 위배됩니다. `vocal` 원자의 `shortForm` 자체는 유지했습니다(진짜 하드 리밋 근접 시에만 작동, 부작용 없음).

`resolvedConstraints`(어휘반복/제목패턴 지시)는 단일팩·멀티셋 경로 모두에 실제로 연결했고(이전에는 계산만 되고 전달되지 않던 죽은 코드였음), 렌더링된 지시문에 실제 숫자(예: "최대 2곡까지만")가 포함됨을 확인했습니다 — 다만 이는 **브릿지/에이전트 경로**에만 영향을 주며, 로컬 생성기는 애초에 이 제약을 소비하는 메커니즘이 없어(템플릿 기반, LLM 아님) 로컬 실측치는 변하지 않는 것이 정상입니다.
